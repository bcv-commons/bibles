# `langs.json` / `langs-mini.json`

`https://cdn.bibel.wiki/catalog/langs.json`
`https://cdn.bibel.wiki/catalog/langs-mini.json`

Per-language display names (`langs.json`) and per-language canon coverage
(both files) — "what languages exist, with what name, and what
NT/OT/OBS coverage." Answers the same questions
[`catalog-index.json`](catalog-index.md) +
[`catalog-audio-index.json`](catalog-audio-index.md) +
`/dbt/<iso>/media.json`'s `timingBooks` already answer *separately*, plus
language display names, which nothing else here publishes at all.

## Status: self-derived, no external dependency (as of 2026-09-03)

This file used to be a byte-for-byte mirror of `bible-story-builder`
(MONO)'s `ALL-langs.json`/`ALL-langs-mini.json` export — a real,
short-lived Phase 1 stopgap, published after that repo went private and
broke a client's build (`demo-bibel-wiki` was fetching those files
directly from `raw.githubusercontent.com` at build time; no GitHub auth
available on their host for a private-repo fetch). That mirror source
(`bcv-commons/bible-story-builder-bak`) is itself a frozen one-time
snapshot (confirmed via the GitHub API: exactly one commit, 2026-07-28) —
it could never gain new languages, including everything `bibles` has
added since, OBS's dialect/subtag expansion included.

**Phase 2 replaced the mirror the same day**: `catalog/langs.json` /
`langs-mini.json` are now generated by
`pipeline/comparison/generate_langs_catalog.py`, derived entirely from
data `bibles` already produces — `catalog-index.json`,
`catalog-audio-index.json`, `/dbt/_app/media-index.json`, and every
`/obs/<iso>/media.json` — with zero dependency on any external repo.
Self-refreshing on every `make langs-catalog` run (after `dbt-metadata` +
`obs-metadata`). Same URLs as the Phase 1 mirror, so no client-side
change needed — content only improved: **2566 languages** (was 2165),
plus a new **`obs`** canon key the mirrored file never had.

## Category derivation

Five categories, derived per `(iso, canon)` from three signals this repo
already tracks independently — not copied from anywhere:

```
TEXT  = catalog-index.json has a row for this (iso, canon), any source
AUDIO = catalog-audio-index.json has a row for this (iso, canon), any source
TIMED = confirmed real per-verse timing exists — DBT-only today, the only
        source with cataloged real timing (see doc/sources.md)
```

| TEXT | AUDIO | TIMED | → category |
|---|---|---|---|
| ✓ | ✓ | ✓ | `with-timecode` |
| ✗ | ✓ | ✓ | `audio-with-timecode` |
| ✓ | ✓ | ✗ | `syncable` |
| ✓ | ✗ | — | `text-only` |
| ✗ | ✓ | ✗ | `audio-only` |

For `nt`/`ot`: `TEXT` collapses `ntp` into `nt` and `otp` into `ot` —
Portions still counts as "has some text." For `obs`: `TEXT`/`AUDIO`/
`TIMED` read directly from each language's own `/obs/<iso>/media.json`
(`storyCount`/`audioStories`/`timingStories` `> 0`) — OBS has no canon or
Portions concept, this is the whole language's coverage in one bucket.

## Shape

```json
{
  "metadata": {"generated_at": "...", "total_languages": 2566},
  "canons": {
    "nt": {
      "with-timecode": {"ben": {"n": "Bengali", "v": "বাংলা", "s": "Beng"}, ...},
      "audio-with-timecode": {...},
      "syncable": {...},
      "text-only": {...},
      "audio-only": {...}
    },
    "ot": {"...same five categories..."},
    "obs": {"...same five categories, but whole-language, no Portions..."}
  }
}
```

`langs.json` has full `{n, v, s}` (English name / vernacular autonym /
ISO 15924 script code) per language per category. `langs-mini.json` is
the same category structure with plain iso-code arrays instead — smaller,
no names, for a coverage-only check.

A language can appear in multiple canon/category combinations (e.g. NT
`with-timecode`, OT `audio-only`, and OBS `text-only` all at once — real,
not hypothetical, e.g. `amh`).

## Language names (`n`/`v`/`s`)

Primary source: `/dbt/_app/media-index.json`'s own name resolution
(`generate_audio_metadata.py`) — helloAO's catalog, then the DBS bible
details cache (`internal-data/api-cache/dbs/bibles/*.json`, which also
supplies `s`, the ISO 15924 script code — a real field, not guessed:
e.g. `"script": "Arab"` sits right in that cache, confirmed 2026-09-03).
Both are live, already-owned sources — reordered ahead of the old frozen
mirror on 2026-09-03 (that file is now only an optional last-resort
fallback for the small number of languages neither live source has;
nothing breaks if it's absent entirely).

Fallback for OBS-only languages neither DBS nor helloAO covers at all
(mostly door43's dialect/private-use-tagged codes, e.g.
`bfz-x-baghati` → `"Baghati"`, roughly 84 of 214 OBS languages as of
2026-09-03): door43's own `language_title` field, captured in
`fetch_obs_repos.py`'s cache. **Not guaranteed to be strictly an English
gloss** the way the DBS/helloAO names are — it's door43's own display
title for that language, used here on a best-effort basis since the
alternative is no name at all.

## One known, accepted discrepancy vs. the old mirrored file

Comparing against the final Phase 1 mirror: 2566 vs 2165 languages, only
**one** (`tsn`, Tswana) present in the old file but absent here. Checked:
`tsn` has a real name in our own data but zero rows in either
`catalog-index.json` or `catalog-audio-index.json` — meaning this repo's
own curated existence signals don't currently confirm any independently
fetchable text or audio for it (see `catalog-index.md`'s note on
excluding DBT rows that aren't genuinely independently fetchable, even
when DBT's raw listing nominally references the language). This may be a
stricter, more accurate result than the old export's claim, not a
regression — not investigated further.
